## Accomplishments
- `VehicleList` component: dense `<table>` on md+ degrading to a stacked `<Card>` list below md (both in DOM, CSS-gated), one row/card per scoped vehicle with plate, brand/model (+ model_year when present), live `StatusBadge`, locale-formatted mileage (`numeric-cell` + " km"), translated fuel **type**, and owner-view agency name resolved client-side from the auth store.
- Filtering: status is a server-side `?status=` filter carried in the query key (refetch per filter); text search is a client-side `useMemo` over plate/brand/model with zero network calls (unpaginated list — no debounce, no slicing).
- Full D-09 state machine: skeleton rows while pending, inline `role="alert"` error banner with a working Réessayer refetch, `EmptyState` at zero vehicles, and a distinct `noResults` paragraph when a filter matches nothing.
- Retired the Phase 1 `/vehicules` placeholder: created `vehicules/index.tsx` (renders `VehicleList`) + a `vehicules/$vehicleId.tsx` stub (typed link target for 02-03), regenerated the route tree cleanly, and updated `placeholders.test.tsx` + `router.test.tsx`.
- Vendored shadcn `table` + `select` primitives into `src/shared/ui/` with **zero** new npm dependencies (verified `git diff package.json` empty for both).

## Decisions Made
- **Route swap moved into Task 1.** `npx tsc -b` (Task 1's gate) typechecks the entire project. `VehicleList`'s `<Link to="/vehicules/$vehicleId">` is typed against the generated route tree, and deleting `vehicules.tsx` breaks its importer `placeholders.test.tsx` — so the detail-route stub, the placeholder deletion, and the placeholders.test edit all had to land together with the component or tsc fails. Task 2 kept the router integration test + full build gate.
- **$vehicleId stub route created here.** The plan's own 02-03 key_links state the detail route "nests under the vehicules/ directory created by plan 02-02", so creating the directory (and a minimal typed target) is the intended seam; 02-03 replaces the stub with `VehicleDetail`.
- **Radix Select kept (not downgraded to dropdown-menu).** It is the semantically correct filter control; I added shared jsdom polyfills so the Select opens/selects under userEvent, rather than falling back.
- **routeTree.gen.ts not committed** — it is gitignored in this repo and regenerated by the predev/prebuild/pretest hooks (verified via `git ls-files` + `.gitignore`), so the plan's "commit the regenerated file" step does not apply to the actual repo convention.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Detail-route stub + route swap pulled into Task 1**
- **Found during:** Task 1 (VehicleList typecheck gate)
- **Issue:** `tsc -b` compiles the whole project; the typed plate `Link` requires `/vehicules/$vehicleId` to be a registered route, and deleting the placeholder breaks `placeholders.test.tsx`'s `./vehicules` import — none of which can be deferred to Task 2 without failing Task 1's own `tsc -b` gate.
- **Fix:** Created `vehicules/index.tsx` + `vehicules/$vehicleId.tsx` stub, deleted `vehicules.tsx`, regenerated routes, and updated `placeholders.test.tsx` inside the Task 1 commit.
- **Files modified:** src/routes/_authenticated/vehicules/{index,$vehicleId}.tsx, src/routes/_authenticated/vehicules.tsx (deleted), src/routes/_authenticated/placeholders.test.tsx
- **Verification:** `npx vitest run src/features/fleet` + `npx tsc -b` both green.
- **Committed in:** 635b0c8

**2. [Rule 3 - Blocking] Shared jsdom polyfills for Radix popper primitives**
- **Found during:** Task 1 (Select interaction test)
- **Issue:** jsdom lacks `hasPointerCapture`/`releasePointerCapture`/`scrollIntoView`/`ResizeObserver`; without them a userEvent.click on the Radix Select trigger/option throws, so the status-filter behavior can't be tested.
- **Fix:** Added guarded no-op polyfills to `src/test/setup.ts` (additive; safe for all tests).
- **Files modified:** src/test/setup.ts
- **Verification:** status-filter test opens the Select and asserts `?status=rented` on the request URL — green.
- **Committed in:** 635b0c8

**3. [Rule 1 - Bug, in test] Error-banner test hardened against ky's built-in retry**
- **Found during:** Task 1 (error-state test)
- **Issue:** A first-call-only 500 handler let ky's built-in GET retry turn the initial fetch into a success, so the query never entered `isError`.
- **Fix:** Return 500 on every call (mirroring the AppShell meError pattern), then `server.use` a healthy handler before clicking Réessayer.
- **Files modified:** src/features/fleet/VehicleList.test.tsx
- **Verification:** error banner asserts, retry recovers — green.
- **Committed in:** 635b0c8
