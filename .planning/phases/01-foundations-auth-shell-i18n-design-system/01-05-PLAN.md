<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input (credentials) -> wheelio-api | Untrusted form input crosses here; backend re-validates + hashes |
| login error surface -> user | Must not leak account-existence (anti-enumeration) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-enum | Information Disclosure | login/signup error rendering | medium | mitigate | Generic error copy only (D-06), mirroring the backend timing-equalizer; the test asserts the message never distinguishes unknown-email from wrong-password. |
| T-01-cred | Information Disclosure | credential handling | medium | mitigate | Password sent over HTTPS POST via the shared client; never client-side-hashed, never logged; no dangerouslySetInnerHTML in the forms. |
| T-01-openredirect | Tampering | post-login navigation | low | accept | No deep-link-then-login return-URL flow exists this phase, so no open-redirect surface. If a return-URL is added later, validate it is an internal route before navigating (flagged per 01-RESEARCH.md Security Domain). |
| T-01-input | Tampering | Zod schemas | low | mitigate | Client-side Zod validation is a UX nicety; backend bindAndValidate re-validates independently. |
</threat_model>
