<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client route guard / nav visibility -> UX | Purely UX; backend re-validates every mutating call |
| /me scope -> nav + switcher rendering | Role data sourced only from backend /me, never re-derived |
| session bootstrap redirect -> /login | Only a failed refresh may redirect (AUTH-02) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-rbac | Elevation of Privilege | NavRail admin-section + route guard | high | mitigate | Nav visibility is UX-only and driven by isOrgAdmin from permissions.ts (sourced from /me); it is NOT a security boundary. The backend independently authorises every owner-only action. Verified by the hidden-button-direct-API human-check above. |
| T-01-refresh | Denial of Service | _authenticated beforeLoad / ensureSession | high | mitigate | ensureSession routes through the plan-03 single-flight client and fetches /me once; concurrent boot requests (/me + /agencies) share the one refresh promise, so shell load cannot trigger the theft-detection logout. |
| T-01-openredirect | Tampering | login redirect | low | accept | No deep-link-then-login return-URL flow exists this phase. If added later, validate the target is an internal route before navigating (flagged, 01-RESEARCH.md Security Domain). |
</threat_model>
