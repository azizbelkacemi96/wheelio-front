## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, dense table row vertical padding |
| md | 16px | Default element spacing, standard card/form padding |
| lg | 24px | Section padding, auth-screen (login/signup) card padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Exceptions (per D-04 dense/compact mandate):**
1. **Dense table/list rows** (first consumed starting Phase 2, but the token must exist now per AUTH-06): row vertical padding = `sm` (8px), cell horizontal padding = 12px (custom, still a multiple of 4) — deliberately tighter than the `md` default to fit more rows per screen for a front-desk agent working quickly.
2. **Auth screens (login/signup) are the one exception to dense density**: use `lg` (24px) card padding, not the dense `sm`/`md` values — these are first-impression, low-frequency screens where the "confident fintech" (D-01) breathing room matters more than density.
3. **Touch targets**: any icon-only interactive control (nav rail icons, agency-switcher trigger, avatar menu trigger) has a minimum 44×44px hit area on touch/mobile viewports regardless of visual density — Apple/Google baseline, non-negotiable given later phases' on-site mobile use.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 (regular) | 1.5 |
| Body | 14px | 400 (regular) | 1.5 |
| Heading | 18px | 600 (semibold) | 1.2 |
| Display | 24px | 600 (semibold) | 1.2 |

Exactly 4 sizes (12/14/18/24), exactly 2 weights (400/600) — no other size or weight is introduced anywhere in this phase's screens. Body is 14px rather than the more generic 16px specifically because D-04 mandates a dense/compact UI (matches Stripe's own dashboard body-text scale).

## Color

Both light and dark values declared together — D-02 requires both to ship from day one, not be retrofitted.

| Role | Value (Light / Dark) | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` / `#020617` (slate-950) | App background, page canvas |
| Secondary (30%) | `#F1F5F9` (slate-100) / `#0F172A` (slate-900) | Cards, sidebar, nav surfaces, table zebra rows |
| Accent (10%) | `#2563EB` (blue-600) / `#3B82F6` (blue-500, lightened for dark-bg contrast) | See "Accent reserved for" below |
| Destructive | `#DC2626` (red-600) / `#EF4444` (red-500, lightened for dark-bg contrast) | Destructive actions only |

**Accent reserved for:** primary CTA buttons (login/signup submit, "create X" actions in later phases), the active nav-item indicator/underline, links, focus rings, the agency-switcher's "currently selected" checkmark/badge, the active tab underline, and the brand mark in the top bar. Never used as a general background fill or for large surface areas — that would blow the 10% budget.

**Destructive reserved for:** the logout item is explicitly **not** styled destructive (see Copywriting Contract — logout needs no confirmation and isn't visually alarming); destructive styling in this phase is limited to inline error text/icons (login failure message, form validation errors) and is reserved going forward for cancel-reservation/cancel-contract buttons and delete-confirmation dialogs in later phases.

**Stripe-like accent treatment (D-01):** the login/signup screens (only) may use a subtle brand gradient background behind the centered auth card — `linear-gradient(135deg, #2563EB 0%, #7C3AED 100%)` (blue → indigo/violet) at low opacity or as a soft top-of-page band. This is the one place a gradient is allowed; the dense dashboard interior stays flat-color per the 60/30/10 split so density and legibility aren't compromised.

**Additional tokens established now for downstream phases (not consumed by Phase 1 screens, but required by AUTH-06's "documented token system" mandate):**

| Token | Light | Dark | Reserved for |
|-------|-------|-------|---------------|
| Success | `#16A34A` (green-600) | `#22C55E` (green-500) | Vehicle "available" badge, contract "closed" state, payment success toast (Phases 2/4/6) |
| Warning | `#D97706` (amber-600) | `#F59E0B` (amber-500) | Vehicle "in maintenance" badge, overdue-return flag (Phases 2/4) |
| Border/muted | `#E2E8F0` (slate-200) | `#1E293B` (slate-800) | Dividers, input borders, disabled states |

## Copywriting Contract

Copy given as **FR (default) / EN**, per AUTH-05.

| Element | Copy |
|---------|------|
| Primary CTA (login) | FR: "Se connecter" / EN: "Sign in" |
| Primary CTA (signup) | FR: "Créer mon compte" / EN: "Create account" |
| Empty state heading (unbuilt nav section placeholder — Véhicules/Clients/Contrats/États des lieux/admin sections not yet implemented in this phase) | FR: "Bientôt disponible" / EN: "Coming soon" |
| Empty state body | FR: "Cette fonctionnalité arrive dans une prochaine mise à jour de Wheelio." / EN: "This feature is coming in a future Wheelio update." |
| Error state (login/signup failure) | FR: "Email ou mot de passe incorrect." / EN: "Incorrect email or password." — **deliberate exception to the usual "problem + next step" pattern**: per CONTEXT.md D-06, this message is intentionally generic with no distinguishing detail and no "next step" (there is no password-reset flow — D-05), mirroring the backend's anti-enumeration timing-equalizer. Do not add a "try again" or "forgot password" suffix. |
| Error state (session hard-expiry — refresh token itself invalid, the one case allowed to redirect per AUTH-02) | FR: "Session expirée — veuillez vous reconnecter." / EN: "Session expired — please sign in again." |
| Error state (`/me` scope fetch fails after a valid-looking token) | FR: "Impossible de charger votre profil." + retry action "Réessayer" / EN: "Couldn't load your profile." + "Retry" |
| Destructive confirmation | **Logout**: no confirmation dialog — immediate action on click, standard SaaS convention (reversible by logging back in, not data-destructive). No other destructive action exists in this phase's scope. |

## UI Considerations

> Populated by the ui-phase UI-consideration probe. Shape-rooted UI *state* coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text). Empty-state and error-state COPY lives in `## Copywriting Contract` above — this section covers state coverage and references those rows rather than restating copy.

Applicable state considerations resolved: **19 covered, 2 backstop, 0 unresolved**

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Login form | ✅ covered | Unfilled form shows placeholder text (e.g. `vous@agence.dz`); submit stays enabled but relies on native/Zod required-field validation on submit attempt — no separate "empty state" screen needed for a form. |
| loading | Login form | ✅ covered | Submit button shows an inline spinner and disables itself for the duration of the request; no full-page loading state. |
| error | Login form | ✅ covered | Generic message per Copywriting Contract row "Error state (login/signup failure)" — never distinguishes unknown-email from wrong-password (D-06). |
| partial | Login form | ✅ covered | Per-field Zod validation (invalid email format, empty password) renders inline below each field before submit. |
| empty | Signup form | ✅ covered | Same placeholder pattern as login; no fields pre-filled. |
| loading | Signup form | ✅ covered | Submit button spinner during the signup call, identical pattern to login. |
| error | Signup form | ✅ covered | Field-level error for "email already registered" (FR: "Cet email est déjà utilisé." / EN: "This email is already in use."); a generic banner for unexpected/network failures. |
| partial | Signup form | ✅ covered | Zod validates org name, email, password strength, first/last name per-field, inline. |
| long-text | Signup form (organization name) | 🧪 backstop | Long organization names must not break the auth-card layout (wrap gracefully, no horizontal overflow) — needs a rendered visual check once implemented; no automated truth exists yet. |
| loading | Primary nav | ✅ covered | Nav renders a skeleton shell while the `/me` scope call resolves after login or page reload; real nav items (and role-gated admin sections) only render once Scope has loaded — never guessed or shown optimistically. |
| error | Primary nav | ✅ covered | Per Copywriting Contract row "Error state (`/me` scope fetch fails...)" — full-shell error banner with Retry, never a silently empty/guessed nav. |
| overflow | Primary nav | ✅ covered | Below desktop breakpoint, nav collapses into an icon-only rail or a shadcn `Sheet` slide-out drawer; full labels only render at desktop widths. |
| long-text | Primary nav (label length) | 🧪 backstop | FR labels ("États des lieux") vs EN equivalents ("Inspections") differ in length; needs a rendered check at both locales that neither causes nav-item wrap/truncation at the standard desktop nav width — not verifiable from spec alone. |
| populated | Agency switcher (owner-only) | ✅ covered | Dropdown lists every agency in the owner's organization by name; the current selection carries the accent-colored active/check indicator (D-10, D-11). |
| zero-one-many | Agency switcher (owner-only) | ✅ covered | **Researcher default (not a CONTEXT.md decision — flag for confirmation at plan time):** when an organization has exactly one agency, the switcher still renders (not hidden) showing that single agency, so the shell layout stays identical across every organization regardless of agency count. |
| overflow | Agency switcher (owner-only) | ✅ covered | List scrolls internally past ~8 visible agencies; each name truncates with ellipsis at a fixed max-width rather than wrapping or widening the dropdown. |
| long-text | Agency switcher (owner-only) | ✅ covered | Truncated names get a native `title` tooltip on hover, consistent with the overflow resolution above. |
| loading | Language switcher | ✅ covered | Locale switch is instant (client-side i18next resource swap, no network round-trip) — no loading state is needed or shown. |
| long-text | Language switcher | ✅ covered | Rendered as icon + 2-letter code (FR/EN) only, immune by construction to translation-length variance. |
| populated | User profile menu | ✅ covered | Shows the authenticated user's display name and role label sourced directly from Scope; logout is the last item, visually separated by a divider. |
| long-text | User profile menu (display name) | ✅ covered | Long names truncate with ellipsis inside the fixed-width menu trigger; full name available via tooltip/expanded menu. |
| empty | Placeholder/stub pages (nav sections not built this phase) | ✅ covered | Copy defined in Copywriting Contract ("Bientôt disponible" / "Coming soon" rows). |
