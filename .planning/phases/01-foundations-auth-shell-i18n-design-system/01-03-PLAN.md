<objective>
Build the three pieces of auth infrastructure every later phase depends on and that are expensive to retrofit: (1) permissions.ts — a literal TypeScript port of wheelio-api scope.go; (2) the Zustand auth store with correct token persistence (access in memory, refresh persisted); (3) the ky API client with the single-flight refresh interceptor. TDD is used because each has a precise, testable I/O contract.

Purpose: AUTH-01 (login + transparent single-flight refresh), AUTH-02 (invisible refresh, redirect only on true refresh failure), and AUTH-03 (role model sourced from /me, never re-derived) all rest on this module. The single-flight refresh queue is non-negotiable — a naive per-request refresh races the API's rotating-refresh theft detection and silently logs the user out.
Output: permissions.ts, store.ts, client.ts, each with tests green.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser JS -> wheelio-api /auth/* | Credentials + tokens cross here; API owns rotation/theft-detection |
| in-memory access token vs localStorage refresh token | Only the refresh token is persisted (accepted compromise, STACK.md) |
| client permissions.ts -> UX gating | Read-only mirror; NOT a security boundary — backend re-enforces every mutation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-refresh | Denial of Service / Spoofing | client.ts afterResponse 401 handler | high | mitigate | Single-flight shared refreshPromise (Pattern 1) so concurrent 401s trigger exactly one /auth/refresh — avoids tripping the API's rotating-refresh theft detection (RevokeAllForUser) that would force-logout the whole session. Proven by call-count test. |
| T-01-xss | Information Disclosure | store.ts persistence | high | mitigate | Access token in memory only; only the refresh token is persisted (partialize). No dangerouslySetInnerHTML in this module, keeping XSS blast radius bounded to a rotating, short-lived-blast refresh token. |
| T-01-replay | Spoofing / Tampering | refreshAccessToken | medium | mitigate | Client never independently retries a refresh with a token it already rotated away from; the single-flight guard prevents the client-side replay symptom. Server-side RevokeAllForUser is the backstop. |
| T-01-rbac | Elevation of Privilege | permissions.ts | high | mitigate | permissions.ts is documented UX-only; every mutating request is independently authorised by wheelio-api Scope. Verified by the plan-06 hidden-button spot-check and this module's port-fidelity tests. |
